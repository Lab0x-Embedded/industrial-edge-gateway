# 工业边缘网关 · 源码阅读路线

> 目标：尽快建立对整个工程的"心理模型"，能定位到"想改的东西在哪"，再进入调试。
> 工程全貌：STM32F407 + FreeRTOS + LVGL8.3，RS485/Modbus 采集 → ESP8266/MQTT 上云 → W25Q128 断网缓存 → 2.8寸触摸屏显示。

**读法总原则：先框架、后细节；沿"数据流"读，不要从驱动文件开始逐个啃。**
整个工程只有一件事在流动：`传感器数据 → 采集 → (缓存/上云) → 显示`。抓住这条流，其它文件都是它的支流。

## 第 1 遍：RTOS 骨架 —— 找到"万物起点"（1 小时）

按调用顺序读，这是整个程序的骨架：

### 1. `Core/Src/main.c`（255 行）
- `SystemClock_Config()`：确认主频 168MHz、`FLASH_LATENCY_5`。
- `main()`：看**初始化顺序**——GPIO→DMA→FSMC→SPI1→USART2→UART4→TIM3→IWDG→RTC→**UART5**。
- `USER CODE BEGIN 2`：`SPI_FLASH_Init` / `FlashCache_Init` / `RS485_RX` / `HAL_UARTEx_ReceiveToIdle_DMA(&huart4,...)`。
- `HAL_TIM_PeriodElapsedCallback()`：TIM3 → `lv_tick_inc(1)`，TIM4 → `HAL_IncTick()`。

### 2. `Core/Src/freertos.c`（159 行）
- `MX_FREERTOS_Init()`：2 个互斥量（`esp_uart_mutex`、`flash_mutex`）+ 2 个队列（`data_queue`、`lvgl_data_queue`，**长度都是 1**）。
- `StartDefaultTask()`：创建 5 个业务任务后自删——`UI` / `Modbus` / `AT` / `MQTT` / `Dog_task`。
- 注意它 `#include "tasks.h"`（原 `Taskhandel.h`）。

### 3. `User/app/tasks.c`（296 行）★ 全工程大脑
5 个任务的实现都在这（原 `Taskhandel.c`）。第一遍只读函数骨架 + 数据流：
- `Modbus()`：每 800ms → `Modbus_Poll_AllDev()` → `Modbus_Upload_Json()` 写队列。
- `MQTT()`：从 `data_queue` 阻塞取；在线则**先补传缓存（≤5条/轮）再发实时**，离线则调 `cloud_build_payload()` + `FlashCache_Write()`。
- `AT()`：每 10s 心跳 `MQTT_SendPing()`，用 `esp_recv_raw()` 等 PINGRESP，连续 3 次失败判离线，离线每 10s `RE_MQTT_Init()` 重连。
- `UI()`：LCD/触摸/LVGL 初始化 → 5ms 循环：息屏/唤醒 + 收 `lvgl_data_queue` 刷界面 + `lv_timer_handler()`。
- `Dog_task()`：每 3s `HAL_IWDG_Refresh()`。

> `tasks.h` 里 `Data_t` 是全局数据载体；`g_mqtt_connected` 现已在此声明。

**这一遍要画出任务间的数据流箭头**（谁写哪个队列、谁读哪个队列、谁抢哪个锁）。

## 第 2 遍：沿数据流打通四条链路（2–3 小时）

### 链路 A：数据从哪来 —— `User/modbus/modbus.c/.h`（361 行）
- `dev_list[]`：**多从机配置表**（改传感器的地方）。
  - `{0x01,0x03,0x0001,2,...}` 温湿度、`{0x02,0x03,0x0002,2,...}` 光照。
- `Modbus_Read_Dev()`：组帧 → `RS485_TX` → 发送 → `RS485_RX` → 轮询收帧 → CRC16 校验 → 解析。
- `Modbus_Poll_AllDev()`：遍历设备，成功按 `dev_addr` 做**量程换算**，失败累加 `err_cnt`。
- `Modbus_Upload_Json()`：打包 `Data_t` 写 `data_queue` + `lvgl_data_queue`。
- `modbus.h`：`RS485_TX/RX` 方向脚宏（PG6）。

> 改传感器地址/寄存器/换算系数 → 全在这个文件。接口相对旧版未变。

### 链路 B：数据去哪存 —— `User/storage/`（w25qxx 342 + cache 168 + log 94 行）
旧 `flash.c` 已拆成三个文件，职责更清晰：
- `w25qxx.c/.h`：SPI Flash 底层（SPI1，CS=PG8），扇区擦除/页写/读；接口名仍是 `SPI_FLASH_*`。
- `cache.c/.h`：**断网补传缓存**（分区 4~8MB）。`FlashCache_Init/Write/Read/HasData/MarkSent/Clear`、`my_clear()`、`MQTT_PublishJson()`。
- `log.c/.h`：**系统日志**（分区 0~4MB 循环写）。`Log_Init()` / `Log_Write()` / `Log_ReadOne()` / `Log_EraseAll()`；对外暴露 `log_write_offset`（日志页倒序读的起点）。
- 分区常量从 `flash.h` 拆到 `cache.h` / `log.h` 各自头文件里。

> **调试注意**：`flash_mutex` 在 Log_Write/Log_ReadOne 与 cache.c（`FlashCache_Init/Write/Read/MarkSent`）中均已生效（cache.c:56 起 take/give）；新增 Flash 调用方务必走同一把锁。

### 链路 C：数据怎么上云 —— `User/net/`（cloud 438 + esp_uart 158 + esp_at 138 行）
- `cloud.h`：**云平台唯一配置源**（IOTSystem/OneNET 切换、Host/凭证/token 都在这里，真实值在根目录 `.env`）。
  - `CLOUD_TARGET` 选平台；`cloud_build_payload()` / `cloud_publish()` 是统一发布出口。
- `cloud.c`：`CloudProfile` 表收敛各平台 topic/QoS/认证差异；**MQTT 组包/解析已并入此文件**（`mqtt_send_connect` / `mqtt_send_subscribe` / `mqtt_wait_connack` / `mqtt_drain_downlink`），另含 `MQTT_Init/RE_MQTT_Init/MQTT_SendPing/esp_recv_raw/dbg_print`。
- `esp_uart.c/.h`：AT 应答的**环形缓冲区**（`RingBuf_Clear/Read`、`Command_Write`）。
- `esp_at.c/.h`：AT 指令收发（`ESP_SendCmd` / `ESP_WaitFor`）。

> 改连自己的云平台 → 只改 `cloud.h`。QoS1 平台以收到 PUBACK 为成功。

### 链路 D：数据怎么显示 —— `User/gui/` + `User/bsp/`
- `User/bsp/lcd.c/.h`：FSMC 并口 ILI9341，`LCD_WritePixels()` 供 LVGL flush 调用。
- `User/bsp/touch.c/.h`：XPT2046（GPIO 模拟 SPI），`TP_Do_Calibration()` / `TP_Get_Calibrated()`。
- `User/gui/porting/lv_port_disp.c`、`lv_port_indev.c`：LVGL 与 LCD/触摸的桥接。
- `User/gui/ui/page_main.c/.h`：**界面本体**，`page_main_create` / `update_data` / `update_status` / **`update_cache`（新增：缓存条数）** / `update_uptime`。
- `User/gui/lv_conf.h`：LVGL 配置（`LV_COLOR_16_SWAP`、`LV_MEM_SIZE` 等）。

> 改界面 → 只动 `gui/ui/page_main.c`；改分辨率/颜色反转 → `gui/lv_conf.h` + `bsp/lcd.h`。

## 调试入手点

1. **串口输出两个出口**：
   - `dbg_print()`（net/cloud.c）→ **UART5（PC12/PD2）115200**，关键事件。
   - `Log_Write()` → 写入 W25Q 日志区（0~4MB），界面日志页可看。
2. **三颗状态灯**（低电平亮，详见 `docs/指示灯.md`）：LED0=PE3（在线实时发布）、LED1=PE4（离线存储/判离线）、LED2=PG9（补传）。
3. **分阶段验证**（务必按此顺序）：屏/触摸 → 最小 UI → 触摸 → Flash → RS485 传感器 → ESP8266 上云 → 开 IWDG 长跑。
4. **两个必须记住的坑**：`LV_COLOR_16_SWAP` 必须为 0（并口屏）；FLASH 等待周期必须 `FLASH_LATENCY_5`。
5. **两个已知 TODO**（`docs/系统架构.md` 末尾）：云端下行指令未分发执行；Modbus 离线设备不跳过、每轮仍全量问询（800ms/台 白等超时）。
