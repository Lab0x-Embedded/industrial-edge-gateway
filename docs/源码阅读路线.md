# 工业边缘网关 · 源码阅读路线

> 目标：尽快建立对整个工程的"心理模型"，能定位到"想改的东西在哪"，再进入调试/面试讲解。
> 前提：手边有板子和 UART5 串口线（PC12/PD2，115200）。**只读不跑，等于白读。**
> 工程全貌：STM32F407 + FreeRTOS + LVGL 8.3，RS485/Modbus 采集 → ESP8266/MQTT 上云 → W25Q128 断网缓存 → 2.8 寸触摸屏显示。
> 代码规模：自研约 2.2 万行，**核心链路只有 ~2600 行**（`app` 570 + `net` 1420 + `modbus` 374 + `storage` 270），UI 3.6k 按需读。

**读法总原则（三条）**

1. **沿数据流读，不要从驱动文件开始逐个啃。** 全工程只有一条主线：`传感器 → 采集 → (缓存/上云) → 显示`，其它文件都是它的支流。
2. **先让板子跑起来再读**：知道"正常长什么样"，代码才有对照物。
3. **读一个文件答一个问题**：答不上来＝没读到，回头再看；答上来就往下走。

> 文中行数供参考，会随改动漂移；以函数名/文件名为准。

## 阶段 1：RTOS 骨架（1 小时）——"万物起点"

按调用顺序读，**只看骨架不钻细节**：

| 文件 | 只看什么 |
|---|---|
| `Core/Src/main.c`（277 行） | `main()` 初始化顺序：GPIO→DMA→FSMC→SPI1→USART2→UART4→TIM3→IWDG→RTC→UART5；USER CODE 区挂 `ReceiveToIdle_DMA` |
| `Core/Src/freertos.c`（163 行） | 2 把锁（`esp_uart_mutex` / `flash_mutex`）+ 2 个队列（`data_queue` / `lvgl_data_queue`，**长度都是 1**）+ 5 个 `xTaskCreate` |
| `User/app/tasks.c`（506 行）★ | 5 个任务循环骨架：`Modbus()` / `MQTT()` / `AT()` / `UI()` / `Dog_task()`；两把锁的 take/give 位置 |

任务与优先级（`freertos.c`）：

| 任务 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| `Dog_task` | AboveNormal+2（最高） | 1KB | 2.5s | 检查心跳→喂 IWDG（10s 超时） |
| `UITask` | AboveNormal | 4KB | 5ms | 息屏/唤醒 + LVGL 刷新 |
| `SensorTask` | Normal+1 | 2KB | 800ms | Modbus 轮询 |
| `NetworkTask`(AT) | Normal | 2KB | 10s 心跳 | 心跳/扫描/重连/校时 |
| `MQTTTask` | Normal | 4KB | 事件驱动 | 发布/补传/离线缓存 |

**自答**：
1. 谁写 `data_queue`、谁读？为什么长度是 1（提示：`xQueueOverwrite` 只留最新值）？
2. AT 与 MQTT **同优先级**、抢同一把锁——为什么必须留让出点（`vTaskDelay(2000)`）？
3. UI 为什么不直接调串口函数？

**验证**：调试器挂起后用 `uxTaskGetSystemState` 看任务状态/栈水位，和上表对得上就过关。

## 阶段 2：四条数据流（2–3 小时，核心）

一条数据走完这四条，项目就通了：

| 链路 | 文件 | 抓什么 |
|---|---|---|
| **A 采集** | `User/modbus/modbus.c`（374） | `dev_list[]` 从机表 → `Modbus_Read_Dev()` 组帧/CRC → `Modbus_Poll_AllDev()` 遍历 + 量程换算 + `err_cnt` 离线判定 → `Modbus_Upload_Json()` 写双队列 |
| **B 上云** | `tasks.c` 的 `MQTT()` + `net/cloud.c`（511） | 在线：先补传（≤5 条/轮）再发实时；离线：`cloud_build_payload()` + `FlashCache_Write()`。`cloud_publish()` 走 QoS1 等 PUBACK；`profiles[]` 收敛平台差异 |
| **C 存储** | `storage/cache.c`（168）、`log.c`（101） | 缓存环形区（128B/条、magic 0xDEADBEEF、补传成功才 `MarkSent`）；日志环形区（76B/条、回卷擦扇区、倒序读 10 条） |
| **D 显示** | `tasks.c` 的 `UI()` + `gui/ui/` | `lvgl_data_queue` → `page_main` 的 `update_data/update_status/update_clock/update_uptime`；5 个页面怎么切；`ui_theme.c` 是唯一色板 + 样式工厂 |

**自答（能画出来就过关）**：
> 一个 25.6°C 读数，从 DHT11 到"云端收到"，经过哪些函数、哪些队列/缓冲、哪把锁？

**验证**：
- 拔从机 → 5 轮后日志出现 `modbus 0x01 offline`，`valid=0` 后 payload 里不再有这个字段
- 拔网线 → LED1 亮、缓存条数增加；插回 → 日志 `BUCHUAN*1` … `BUCHUAN Finish`

## 阶段 3：网络细节（1–2 小时，最容易踩坑也最值钱）

一层包一层读，顺序不要乱：

```
esp_uart.c   UART4 DMA 空闲中断 → 2048B 环形缓冲（单生产者/单消费者，无锁）
    ↓
esp_at.c     ESP_SendCmd：逐行匹配 OK / CONNECT / ">"，每收一字节重置超时
    ↓
cloud.c      MQTT 组包/解析、CIPMODE=1 + CIPSEND 进出透传、CONNACK 校验
    ↓
wifi_conn.c  扫描（CWLAP + 静默窗口）、入网（CWJAP + 超时重试）、SNTP 校时、凭据存档
```

**自答**：
1. AT 模式与透传模式怎么互相切？`+++` 为什么要求前后各 20ms 静默？
2. 扫描为什么异步（UI 只置 `wifi_scan_request`）？结果怎么回到界面、怎么排序？
3. 入网失败会写哪几条日志？分别对应密码错、信号弱、模块不应答中的哪一种？

**验证**：点「WiFi 列表」看 UART5 输出；故意输错密码，日志应出现 `wifi denied`（而不是 `timeout`）。

## 调试入手点

1. **两个输出出口**：`dbg_print()` → UART5（PC12/PD2，115200，关键事件/hex dump）；`Log_Write()` → W25Q 日志区（屏幕日志页可看，按级别三色）。
2. **三颗状态灯**（低电平亮，详见 `docs/指示灯.md`）：LED0=PE3 在线发布 / LED1=PE4 离线存储 / LED2=PG9 补传。
3. **分阶段验证顺序**：屏/触摸 → 最小 UI → 触摸 → Flash → RS485 传感器 → ESP8266 上云 → 开 IWDG 长跑。
4. **两个必须记住的坑**：`LV_COLOR_16_SWAP` 必须 0（并口屏）；FLASH 等待周期必须 `FLASH_LATENCY_5`。
5. **已知问题 / 待办**（详见 `docs/系统架构.md` 末尾）：
   - 云端下行指令**已订阅但未派发执行**（`mqtt_drain_downlink` 只解析，没有命令表）；
   - Modbus 离线设备**不跳过**，每轮仍全量问询（800ms/台 白等；`MAX_ERR_CNT` 的 `continue` 被注释掉）；
   - 运行中"强制重新校准"入口未做（现在只能按住屏幕开机触发）。

## 文档/代码里已知的小瑕疵（改动时可顺手清理）

- `User/bsp/w25qxx.h` 的 `sFLASH_ID` 仍写 `0xEF4017`（W25Q64 的 ID），实际板载是 **W25Q128**——不影响功能，读代码时别被误导。
- `README.md` 的"目录结构"段已更新为新模块名（`app/net/storage` + `clock.c`/`wifi_conn.c`）；若看到旧路径，以本文"工程全景"为准。
- `docs/系统架构.md` 里 TIM3 心跳写成"1ms 设计意图"，实际 PSC=99/ARR=999 @84MHz ≈ **1.19ms**（该文件已有备注）。
