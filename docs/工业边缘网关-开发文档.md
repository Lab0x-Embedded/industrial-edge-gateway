# 1. 项目概述

## 1.1 项目背景

工业现场的温湿度、光照等环境量多由 RS485 总线上的 Modbus 从机（传感器/变送器）提供，而云端监控平台走 MQTT/以太网。两者之间缺少一个**边缘侧的桥接与缓冲设备**：现场无人值守、网络可能间歇中断，需要在本地完成采集、显示、缓存与断网续传。本项目即为此开发的工业边缘网关：STM32F407 + FreeRTOS 的嵌入式固件，南向 Modbus RTU 采集、北向 MQTT 上云，本地触摸屏监控，断网数据不丢。

## 1.2 项目目标

- **功能目标**：Modbus RTU 主站轮询 2 台从机（温湿度/光照）；MQTT（QoS1）上报 OneNET / 自建 IOTSystem 双平台（编译期切换）；断网数据落 SPI Flash 缓存、恢复后限速补传；LVGL 中文触摸界面（实时仪表、WiFi 配置、日志查看）；系统循环日志与三色 LED 状态指示。
- **性能目标**：采集周期 800ms（设备间隔 30ms）；补传每轮 ≤5 条、PUBACK 确认；云端心跳 10s；UI 渲染循环 5ms、LVGL 刷新周期 30ms；Debug 构建资源占用 Flash ≈441KB/1MB（42%）、RAM ≈114KB/128KB（87%）。
- **可靠性目标**：IWDG 20s 看门狗（异常必复位自愈）；UART 溢出错误自动恢复接收；三层在线判定（显示 25s 新鲜度 / 决策 3 连败 / 平台 keepalive）避免假在线；断电后缓存分区扫描续写；W25Q 写入带 magic + 校验和 + 写后回读。
- **可扩展目标**：新增云平台 = profile 表加一行；新增从机 = dev_list 加一条；界面主题集中一处（ui_theme）。

## 1.3 适用范围

覆盖：本仓库网关固件（`User/` + `Core/`）、配套从机固件（`ModbusSlave/` 独立工程）、PC 端联调工具（`tools/`）、双云平台（OneNET Studio / 自建 IOTSystem）接入。
不涉及：OTA 远程升级、硬件电路设计/量产工艺、运维平台侧开发。

# 2. 系统总览

## 2.1 系统简介

通过 RS485/Modbus RTU 采集两台从机（0x01 DHT11 温湿度、0x02 光敏 ADC 光照）数据，经 ESP8266 透传 TCP 上报 MQTT 云平台（OneNET / 自建 IOTSystem，编译期 profile 切换，QoS1 + PUBACK 确认）；断网期间有效数据以 JSON 落 W25Q128（4~8MB 分区）缓存，恢复后每轮限速补传 ≤5 条；本地 2.8 寸 ILI9341 触摸屏（LVGL）实时展示仪表与状态，支持屏上配置 WiFi、查看环形日志；IWDG 看门狗 + 三色 LED 保证无人值守可靠性与现场可诊断性。

## 2.2 系统架构图

详细架构与数据流见 `docs/系统架构.md`（含 Mermaid 架构图与时序图），此处为摘要：

```
 从机板(F407)×2                网关（STM32F407ZGT6 + FreeRTOS）                     云平台
 ┌───────────┐   RS485    ┌─────────────────────────────────────────┐   ESP8266   ┌──────────┐
 │0x01 温湿度 │◄─Modbus───►│ SensorTask ─► data_queue/lvgl_queue     │◄─MQTT透传──►│ OneNET /  │
 │  DHT11    │   RTU 0x03 │      │             │          │          │  UART4+DMA │ IOTSystem│
 │0x02 光照   │            │      ▼             ▼          ▼          │             └──────────┘
 │  ADC      │            │  W25Q缓存/补传   UI任务     AT任务(MQTT任务)│
 └───────────┘            │  W25Q日志      LVGL+LCD    心跳/重连/扫描  │
                          │  Dog_task: IWDG 喂狗（最高优先级）          │
                          └─────────────────────────────────────────┘
```

## 2.3 数据流说明

**采集 → 处理**：SensorTask 每 800ms 依次问询 `dev_list[]` 两台从机（Modbus 0x03），应答经四重校验（长度/地址/功能码/CRC）后按量程换算写入设备表，同时维护 `err_cnt`（连续 5 次失败判离线、恢复记日志）与 `valid` 有效性掩码。

**分发**：`Modbus_Upload_Json()` 把设备表打包成 `Data_t{temp,shi,light,valid}`，用 `xQueueOverwrite` 同时写进两个**长度为 1** 的队列——`data_queue`（MQTT 任务阻塞消费）与 `lvgl_data_queue`（UI 任务非阻塞消费）。队列满即覆盖，语义是"永远只保留最新值"，因此**UI 刷新不依赖云端在线**。

**上报/缓存**：MQTT 任务从 `data_queue` 醒来——在线：持 `uart1_mutex` 先补传缓存（≤5 条，逐条 PUBACK 确认后 MarkSent）再发实时数据；离线：`valid≠0` 时把 JSON 写入 W25Q 缓存分区。

**显示**：UI 任务 5ms 循环跑 `lv_timer_handler`，顺手非阻塞收 `lvgl_data_queue` 刷仪表；状态字（ONLINE/NO CLOUD/OFF）按 25s 云端应答新鲜度刷新。

## 3.4 外设接口说明

- **RS485（USART2，9600-8N1）**：半双工，发送前拉高 PG6、阻塞发送（1000ms 超时）返回后立即切回收；发送前先清 ORE 标志 + 空读 DR 清残留。帧结束判定：50ms 无新字节（软件 T3.5，标准值 9600 下约 4ms，此处取保守值）+ 800ms 绝对超时兜底。
- **ESP8266（UART4，115200-8N1）**：RX 走 `HAL_UARTEx_ReceiveToIdle_DMA`（DMA1_Stream2，NORMAL 模式、字节、MINC），落地 256B 缓冲后由空闲中断回调拷入 2048B 无锁环形缓冲并重挂 DMA；半传输中断（HT）关闭，保证"一段数据一次回调"。错误回调实现 ORE 清标志 + 重挂（HAL 默认空弱回调会静默杀死接收）。
- **FSMC（LCD）**：Bank1/NORSRAM4，16 位宽，ExtendedMode 读写分开：读 ADDSET=15/DATAST=60，写 ADDSET=9/DATAST=8（Mode A）。RS 接 A12——16 位总线上对应字节地址 bit13：命令地址 `|0x1FFE`、数据地址 `|0x2000`。
- **SPI1（W25Q128）**：主机、模式 0（CPOL=0/CPHA=1edge）、8 位 MSB、预分频 8 → ≈10.5MHz；CS 用 GPIO（PG8）。驱动上电自愈：状态寄存器 BP 保护位（SR&0x1C）非零则写 0 清除，否则擦写静默失败。
- **IWDG**：LSI（typ 32kHz，手册 DS8626 只保证 17~47kHz）÷256 × 重装 2500 = **标称 20s** 超时（实际 13.6~37.6s）；Dog_task 每 3s 喂（余量 ≈6.7 倍）。注意它是独立最高优先级任务**无条件**喂 → 只兜"全局挂死"（断言死循环、时钟/调度器停摆、HardFault 挂死），**抓不到单任务卡死/饥饿或业务失效**。一旦启动不可关闭。
- **RTC**：时钟源 LSI（±5% 是常温经验值；手册 DS8626 全温区只保证 17~47kHz，接近 ±47%。只做掉电兜底，不做走时主钟）；走时 = HAL_GetTick（HSE 晶振精度）+ SNTP 校时。**注意电源域**：LSI/HSE 在 VDD 域，断电即停振；只有 **LSE 在备份域**，VBAT 供电时才能继续走时。所以"有电池就能保持时间"只在 RTC 走 LSE 时成立——走 LSI 时电池只保住寄存器内容，时间停在断电那一刻；`Clock_Init` 用 `RTC_UsesLse()`（读 `RCC->BDCR.RTCSEL`）区分两者，只有 LSE 才敢把 RTC 数据当已校时，否则报未校时（界面暗色/日期 `--`）等 SNTP 重新对上。
- **时钟树**：HSE 8MHz → PLL（M=4/N=168/P=2）→ SYSCLK 168MHz；APB1 ÷4=42MHz（定时器 ×2=84MHz），APB2 ÷2=84MHz；FLASH_LATENCY_5；CSS 开启。

## 3.5 电气参数

- 供电：USB 5V 输入经板载 LDO → 3.3V；MCO/SWD/外设电平 3.3V（SWD 排针严禁接 5V，调试手册 #12 案例）。

# 4. 软件设计

## 4.1 软件架构分层

```
app/        业务编排（tasks.c 五任务 + clock.c 时间服务）—— 锁的唯一持有层
modbus/     Modbus RTU 主站协议（无锁，纯协议）
net/        esp_uart(环形缓冲) → esp_at(AT 驱动，无锁) → wifi_conn(连接管理) → cloud(MQTT/profile)
storage/    log.c / cache.c（建立在 bsp/w25qxx 之上，flash_mutex 在驱动层持有）
bsp/        lcd.c / touch.c / w25qxx.c 板级驱动
gui/        LVGL 源码 + porting（显示/输入对接）+ ui（页面）+ ui_theme（样式集中）
```

层间规则：协议层不知传输细节、业务层不知寄存器；所有 lv_* 调用仅在 UI 任务（LVGL 非线程安全）；ESP 串口访问统一由 `uart1_mutex` 串行化（锁在业务层，`*_locked()` 后缀函数内部禁止再拿锁）；W25Q 全芯片访问由 `flash_mutex` 在 w25qxx 驱动层串行化。

## 4.3 任务设计（FreeRTOS）

由 defaultTask（512B 栈，启动后自删）创建五个业务任务（`Core/Src/freertos.c:144-148`，栈单位为"字"=4 字节）：

| 任务名 | 优先级 | 栈大小 | 周期 | 职责 |
|---|---|---|---|---|
| UI（UITask） | AboveNormal(32) | 1024 字（4KB） | 5ms | lv_timer_handler、数据刷新、息屏/唤醒、时钟显示 |
| Modbus（SensorTask） | Normal+1(25) | 512 字（2KB） | 800ms | 轮询 RS485 从机、维护 dev_list/valid、双队列分发 |
| AT（NetworkTask） | Normal(24) | 512 字（2KB） | 10s（切 10×1s 便于插队） | ESP 通道心跳/重连/扫描/校时、RX 自愈 |
| MQTT（MQTTTask） | Normal(24) | 1024 字（4KB） | 事件驱动（data_queue） | 在线补传+实时发布；离线写缓存 |
| Dog_task | AboveNormal+2(34) | 512 字（2KB） | 3s | 喂 IWDG（20s 超时），全系统最高优先级 |

> MQTT 栈 512→1024 字的依据：`-fstack-usage` 最坏链 publish→PUBACK 解析→Log_Write→printf ≈2.9KB，运行期 `uxTaskGetSystemState` 实测 512 字时最小剩余仅 3%。

**任务间同步机制**：
- 队列 ×2：`data_queue` / `lvgl_data_queue`，均**长度 1**、元素 `Data_t`，写侧 `xQueueOverwrite`（mailbox 语义，永远保最新值）；MQTT 阻塞收、UI 非阻塞收。
- 互斥量 ×2：`uart1_mutex`（ESP 串口整段事务，MQTT/AT 两任务争用，全部 `portMAX_DELAY`）；`flash_mutex`（W25Q 全芯片，log/cache/凭据/校准四方共用，w25qxx 层持有）。
- volatile 标志组：`wifi_scan_request / wifi_timesync_request / wifi_reconnect_request`（UI 置位、AT 任务持锁消费），结果经 `wifi_scan_state / wifi_timesync_result / wifi_ap_list[]` 回流。
- **锁公平性约定**：MQTT 与 AT 故意同优先级，MQTT 每轮循环末尾 `vTaskDelay(2000)` 让位（历史上因多余的 `}` 使该延时成为死代码，引发锁车队饿死，见调试手册）。

## 4.4 模块详细设计

### 4.4.1 采集模块（modbus）

**从机配置表**（`modbus.c:118-121`）：

| 从机地址 | 功能码 | 起始寄存器 | 数量 | 数据含义 | 换算 |
|---|---|---|---|---|---|
| 0x01 | 0x03 | 0x0001 | 2 | 温度 / 湿度（×10 定点） | reg/10.0f |
| 0x02 | 0x03 | 0x0002 | 2 | 光照（32 位拆两寄存器，大端） | ((r0<<16)\|r1)/1000.0f |

**帧格式**：请求 8 字节 `[addr][03][regHi][regLo][cntHi][cntLo][CRC_L][CRC_R]`（CRC 低字节在前）；应答 9 字节 `[addr][03][04][d0..d3][CRC_L][CRC_R]`。应答校验：长度、地址、功能码、数据字节数=寄存器数×2、CRC 重算，任一不符整帧丢弃计一次失败。

**CRC16**：Modbus 标准（多项式 0x8005 反射 0xA001、初值 0xFFFF、低字节在前）。双实现：发送用 256 项查表（快），接收校验用逐位异或——两套互为交叉验证。

**超时与重试**：单次发送 1000ms；应答帧间隔判定 50ms；绝对超时 800ms；从机间隔 30ms；全周期 800ms。连续失败 `MAX_ERR_CNT=5` 次判离线（置 valid=0、ERROR 日志），**判离线后继续轮询**等待复活（恢复记 INFO "back online"）。

**数据有效性门控**：`valid` 语义 = "上电以来至少成功读到一次"。MQTT 组包时 valid=0 的字段不出现在 payload；离线时 valid=0 的数据不写缓存——**全 0 假数据永远不上云**。`Data_t.valid` 为掩码：bit0=温湿度、bit1=光照。

### 4.4.2 存储模块（storage）

外接 W25Q128（**16MB** SPI NOR，4KB/扇区）。分区划分（详见 `docs/存储布局.md`）：

| 分区 | 起始地址 | 大小 | 用途 |
|---|---|---|---|
| 日志区 | 0x000000 | 4MB | 系统日志（循环写，76B/条） |
| 补传缓存区 | 0x400000 | 4MB | 断网数据缓存（128B/条） |
| 触摸校准 | 0xF00000 | 4KB | 两点校准参数（magic "TPC1" + 累加和） |
| WiFi 凭据 | 0xF01000 | 4KB | 设置页保存的 SSID/密码（magic "WIFC" + 累加和 + **写后回读校验**） |
| （其余） | — | ≈8MB | 空闲可扩展 |

跨任务互斥：所有 Flash 读写擦经 `flash_mutex` 全芯片互斥（`w25qxx` 驱动层持有）；驱动上电自愈 BP 保护位；`WaitForWriteEnd` 用 500ms 墙钟超时（扇区擦除典型 45ms/最坏 400ms）且**所有退出路径都拉高 CS**。

#### 4.4.2.1 日志区设计方案

1. 检验日志内容有效性设计魔数：`LOG_MAGIC 0x55AA`（置于结构体**末尾**的 `uint32_t`，使 `sizeof` 恒为 76 无填充歧义——历史上 uint16_t 版本曾出现 72/76 二义导致日志错位）。
2. 读写 FLASH 内容都需要对互斥量 `flash_mutex` 进行 P/V 操作。
3. 条目结构：`{time_stamp(HAL_GetTick 运行时长) 4B, level 4B, content[64], magic 4B}` = 76B。
4. 核心写日志代码：

```c
/* 循环日志：写满回卷。NOR FLASH 只能从 1→0，进新扇区先擦除；条目不跨扇区 */
if ((log_write_offset + LOG_OBJ_SIZE) > LOG_PART_SIZE)          //情况1：写入位置超出日志分区大小
    log_write_offset = 0U;
if (((log_write_offset & 0xFFFU) + LOG_OBJ_SIZE) > 0x1000U)     //情况2：写入位置跨扇区边界
{
    log_write_offset += 0x1000U - (log_write_offset & 0xFFFU);
    if ((log_write_offset + LOG_OBJ_SIZE) > LOG_PART_SIZE)
        log_write_offset = 0U;
}
if ((log_write_offset & 0xFFFU) == 0U)                          //情况3：写入位置在扇区起始地址 → 擦除该扇区
    SPI_FLASH_SectorErase(LOG_PART_ADDR + log_write_offset);

part_write(LOG_PART_ADDR, log_write_offset, (uint8_t *)&log_buf, LOG_OBJ_SIZE);
log_write_offset += LOG_OBJ_SIZE;
```

> 注：重启后 `log_write_offset` 归零重写（日志不跨重启续写，时间戳语义为运行时长，续写旧条目意义有限）。

#### 4.4.2.2 断网缓存设计方案

条目 `CacheEntry_t` = **128B**：`{magic 4B, timestamp(HAL_GetTick) 4B, data_len 2B, data[116]}`，data 为一条上报 JSON。魔数：`0xDEADBEEF`=有效待补传，`0xFFFFFFFF`=空/已消费。

- **写入**（MQTT 任务离线分支，`valid≠0` 才写）：条目按 128B 顺写；写地址到扇区边界（4096 对齐）先擦该扇区；写满分区回卷到起点并擦扇区 0（丢最旧）。
- **断电恢复**：`FlashCache_Init` 开机从分区头线性扫描，遇到第一个非有效魔数停——该位置即断电前写地址，续写不丢已存数据。
- **补传**（在线分支）：每轮 `while (FlashCache_HasData() && count<5)`——读一条 → `MQTT_PublishJson`（发布后等 PUBACK）→ 成功才 `FlashCache_MarkSent()` + 日志 `BUCHUAN*1`，条间 800ms 节流；**失败即 break 不标记**，下轮重发同一条。`FlashCache_Read` 内部另有 `read_cnt≤5` 上限，触顶强制读/写指针同步（`my_clear`）放弃剩余积压——防串口锁被长期霸占（见已知问题）。
- **MarkSent**：只重写魔数、不擦除（NOR 物理上把 0xDEADBEEF 改写为 0xFFFFFFFF 是 no-op，"已发"状态的持久化实际依赖内存指针——已知技术债，见 9.3/系统架构待办）。

| 字段 | CLOUD_IOTSYSTEM | CLOUD_ONENET | 说明 |
|---|---|---|---|
| host | IOTSYSTEM_HOST | ONENET_HOST | 服务器地址（.env 注入；IOTSystem 为自建平台，见 github.com/Lab0x-Embedded/iotsystem） |
| port | 1883 | 1883 | MQTT 明文端口 |
| proto_name / level | "MQTT" / 4 | "MQTT" / 4 | v3.1.1 |
| connect_flags | 0xC2 | 0xC2 | 1100_0010b：用户名+密码+Clean Session |
| client_id | IOTSYSTEM_DEVICE_ID | ONENET_DEVICE_ID | 客户端 ID |
| username | IOTSYSTEM_PRODUCT_KEY | ONENET_PRODUCT_ID | 用户名 |
| password | IOTSYSTEM_DEVICE_SECRET | ONENET_TOKEN | 密码 / 鉴权 token（`et=` 到期需重生成） |
| keepalive | 60 | 120 | 心跳间隔（秒，MQTT CONNECT 报文内） |
| topic_pub | "devices/" ID "/data" | "$sys/{pid}/{dev}/thing/property/post" | 发布主题 |

| qos1 | 1 | 1 | 发布用 QoS 1，等待 PUBACK |

**建连流程**（`MQTT_Init`）：逃逸透传（带静默窗口+确认+重试）→ CWMODE=1 → **CWAUTOCONN=0（重试到 OK，≤10 次**，防模块自连 busy 窗口吞命令）→ CWJAP 入网（TIMEOUT 重试 4 次、ERROR 仅 1 次）→ CIPMUX=0 → **SNTP 校时（必须在此位置**：CIPMUX=0 之后、CIPSTART 之前，建链后再逃逸会得到假透传）→ CIPMODE=1 → CIPSTART（5s）→ CIPSEND 确认 `>` 进透传 → MQTT CONNECT/CONNACK（3s，失败 hex dump）→ SUBSCRIBE → 置在线 + 应答时间戳。

**心跳与在线判定（三层）**：AT 任务每 10s 发 PINGREQ（`C0 00`）、1s 内等 PINGRESP（`D0 00`）；连续 3 次失败（≈30s）才 `g_mqtt_connected=0` 走重连（防单次抖动）。**显示层**用 25s 应答新鲜度：只有 CONNACK/PUBACK/PINGRESP 这些云端真实字节刷新 `g_cloud_alive_tick`，超窗 UI 即显示离线——消除"屏上在线、平台已掉线"的幽灵窗口（`cloud_online_now()`，tasks.c:58）。

**断线重连**（`RE_MQTT_Init`）：逃逸透传 → **AT+RST → wifi_at_wait_ready(8s)**（模块复位后 1~3s 才应答，用探测替代盲延时）→ 关自连 → 入网 → CIPMUX/CIPMODE → CIPSTART → 透传 → CONNECT/CONNACK。

**下行处理**：`mqtt_drain_downlink` 在每次发布后收割：解析 PUBLISH（首字节高 4 位 0x3）、1~4 字节变长剩余长度、`[tlen][topic][pid][payload]`；含 `"code"` 的回执写日志（`code:0` 成功 / `10411` 物模型标识符不符等）。畸形帧逐字节排水保持字节流对齐。指令**派发执行**尚未实现（见待办）。

**AT 驱动要点**：总超时语义（非空闲超时——CWJAP/CIPSTART 有 3~15s 静默期）；FAIL/ERROR 先于期望关键字匹配（"CONNECT FAIL" 含 "CONNECT"）；`+++` 逃逸必须先裸探测 AT×2 确认在透传（命令模式下发 +++ 会永久卡死 AT 解析）；进入透传逐字节等 `>`（它不带换行）。接收链：DMA+空闲中断 → 2048B 无锁环形缓冲（SPSC、留一空槽防满/空歧义、`uint16_t` 索引防 256 截断）→ `esp_recv_raw` 字节泵。

### 4.4.4 显示模块（gui / bsp）

**总体设计**

```
User/bsp/          lcd.c（ILI9341 驱动）  touch.c（XPT2046 驱动）
User/gui/porting/  lv_port_disp.c（显示对接）  lv_port_indev.c（触摸对接）
User/gui/ui/       ui_theme.c + 5 个页面
User/app/tasks.c   UI 任务：主循环、息屏管理、数据分发
User/gui/lv_conf.h LVGL v8 版本配置（48KB 内存池 / RGB565 / 30ms 刷新周期）
```

**硬件链路**：ILI9341 2.8 寸、8080 16 位并口走 FSMC NE4（0x6C000000，RS 接 A12 用地址 bit13 区分命令/数据，lcd.h:7）；触摸是 XPT2046 电阻屏 GPIO 模拟 SPI；背光脚 PF10、320×240 横屏（MADCTL=0x68 = MX|MV + **BGR=1**，此面板实测需 BGR 位；0x3A=0x55 RGB565；LV_COLOR_16_SWAP=0）。

**1. 首页设计**：顶栏中文标题 + 日期 + WiFi/云状态字；温/湿双弧盘仪表（lv_arc，温度 -10~100°C / 湿度 0~100%RH）+ 实时时钟（SNTP 未校准显暗色）+ 运行时长 + 设置入口；光照数值卡。

**2. 设置页面**：四个入口（WiFi 配置 / 系统运行日志 / 同步当前时间 / 关于设备）。

**3. WiFi 页面**：SSID 输入框 + 扫描按钮（全屏模态列表，按 RSSI 排序、显示 dBm）、密码框（可切换明暗文）、连接按钮；底部 320×128 常驻键盘（中文字体）。扫描完全异步：UI 只置标志，AT 任务持锁执行 ~12s，界面 500ms 轮询结果不卡顿。

**页面刷新机制**：核心是 UI 任务 **5ms 主循环 + 单元素覆盖队列 + 差值刷新**，没有任何"整页重绘"的概念。数据通路：Modbus 任务每 800ms 轮询 → `modbus.c` 把最新值 `xQueueOverwrite` 进 `lvgl_data_queue`，不管设备在线还是离线都会接收从机数据（UI 刷新与云端状态解耦）。所有 lv_* 调用仅在 UI 任务内（LVGL 非线程安全）。

**触摸校准**：touch.c 是一套完整的"校准—持久化—重校"闭环，驱动时序对齐厂商例程（1µs/时钟沿、命令后 6µs 建立、16 位读数取高 12 位）。两点校准（左上 (20,16) / 右下 (299,223) 十字，每点 16 次采样取平均、逐轴仿射换算并钳位）；初次烧录时检查参数是否存 W25Q128 0xF00000（日志区 <4MB、补传缓存 4~8MB 之后的空闲区），结构体带魔数 "TPC1" + 累加和双重校验，读回不对（坏块/擦写中断）就当没校准过，重新走校准流程；只在开机时读写一次，与运行期日志/补传写入无并发。强制重校入口：开机校准界面出现后 **500ms 采样窗口内 50 次采样有 ≥30 次检测到按下**即判定"按住屏幕开机"，忽略旧校准数据强制重走两点校准（换板/换屏/漂移通用）。

**息屏策略**：实现于 tasks.c 的 UI 任务函数——每轮循环检测 PEN 引脚，按下即刷新 `idle_tick`；**10 秒无操作**关背光（PF10=0）；唤醒**只认触摸**：检测到按下先点亮背光并调 `lv_indev_wait_release()` 吞掉唤醒那次按压（防误触按钮）。另有传感器数值跳变亮屏（温度 >3°C / 湿度 >3%RH / 光照 >10lux，page_main_update_data 内），但**云状态变化只刷新显示不亮屏**（状态 25s 新鲜度窗口在扫描/重连期会翻转，曾导致"板子一会儿自己亮"）。

### 4.4.5 任务编排（app）

启动顺序：`main()` 外设初始化（GPIO→DMA→FSMC→SPI1→USART2→UART4→TIM3→IWDG→RTC→UART5）→ 用户块（W25Q 初始化/自愈、TIM3 启动、Log_Init、FlashCache_Init 断电恢复、Clock_Init、RS485 默认接收、UART4 DMA 首挂）→ osKernelStart → defaultTask 创建 5 业务任务后自删。

共享数据：`dev_list[]`（采集真值源）、`Data_t` 双队列、volatile 标志组（UI↔AT）、`g_mqtt_connected`/`g_cloud_alive_tick`（在线判定）。异常处理：任何断言失败 → 关中断死循环 → IWDG 20s 复位（自愈即重启重试）；复位周期 ≈ 看门狗超时是软死锁的排障指纹。

## 4.6 状态机 / 运行流程

**在线/离线判定**（三层时间常数错位是设计点）：

```
显示层（最快）：cloud_online_now() = g_mqtt_connected && (now - g_cloud_alive_tick) < 25s
                │  alive_tick 仅被 CONNACK / PUBACK / PINGRESP 刷新（云端真实字节）
决策层（防抖）：心跳 10s 一次，连续 3 次失败（≈30s）→ g_mqtt_connected=0 → 触发重连
平台层（最慢）：keepalive（IOTSystem 60s / OneNET 120s）超时平台侧标离线（不受本端控制）
```

**断网→补传全流程**：断网（3 连败）→ MQTT 任务每轮把 valid 数据 JSON 写 W25Q 缓存（LED1 亮）→ 网络恢复 → 在线首轮：补传循环（≤5 条，PUBACK 确认才 MarkSent，LED2 亮）→ 实时数据发布（LED0 亮）→ 2s 让位 → 下一轮继续直至缓存清空。

# 5. 通信协议

## 5.1 Modbus RTU

链路：USART2，**9600-8N1**，半双工 RS485（方向 PG6 高发低收）。仅用功能码 **0x03（读保持寄存器）**。寄存器映射见 4.4.1。异常处理：从机侧对地址不符/CRC 错/寄存器越界一律**静默丢弃**（绝不应答坏帧，错误恢复靠主站超时重试）；主站侧校验失败按"本次失败"计 err_cnt，5 次判离线但继续轮询。

## 5.2 MQTT / 云平台

Broker/认证/主题/QoS/KeepAlive 见 4.4.3 profile 表。无遗嘱消息（LWT 未使用）。QoS1 发布以收到 PUBACK（2s 超时）为成功依据；下行为 SUBSCRIBE 订阅的 set/exec 主题 + 平台回执。

## 5.3 数据格式规范

上行 payload 按 profile 出（`cloud_build_payload`，只含 valid 字段）：

```
IOTSystem（datapoints）:
{"datapoints":[{"metric":"temperature","value":21.5},{"metric":"humidity","value":55.0},{"metric":"light","value":123}]}

OneNET（物模型属性上报，id 为开机秒数）:
{"id":"3721","params":{"temperature":{"value":21.5},"humidity":{"value":55.0},"light":{"value":123}}}
```

下行（订阅主题 + 平台回执）示例：`{"id":...,"code":0,...}`（code=0 成功；10411=物模型标识符不符，整条拒收）。属性标识符必须与平台控制台逐字一致。

# 6. 接口说明

## 6.1 内部模块接口

| 模块 | 接口 | 说明 |
|---|---|---|
| modbus | `Modbus_Poll_AllDev()` | 轮询所有从机（含离线判定/恢复日志） |
| modbus | `Modbus_Upload_Json()` | 打包 Data_t 写双队列（含 valid 掩码） |
| modbus | `MQTT_SendAllDev_NoWait()` | 从 dev_list 取最新值直接发布（valid=0 不发） |
| net | `cloud_build_payload(out,n,d)` | 按 profile 组 JSON（只含 valid 字段） |
| net | `cloud_publish(payload)` | 统一云端发布，QoS1 等 PUBACK，0=成功 |
| net | `MQTT_Init()` / `RE_MQTT_Init()` | 建连 / 断线全量重连（AT+RST 起） |
| net | `wifi_join()` / `wifi_scan_locked()` / `wifi_time_sync_locked()` | 入网 / 扫描 / SNTP（须由持锁方调用） |
| storage | `FlashCache_Write/Read/HasData/MarkSent()` | 断网缓存读写与标记 |
| storage | `Log_Write(level, fmt, ...)` | 系统日志统一入口（镜像 UART5） |
| app | `Clock_SetDateTime()/GetDateTime()/IsSynced()` | 时间服务（tick 走时 + RTC 兜底） |

调用约束：`*_locked()` 后缀函数内部**不再**获取 `uart1_mutex`，由调用方（tasks.c）按事务持锁；所有 W25Q 访问走 w25qxx 层（flash_mutex 已含）。

## 6.2 对外接口

- **对云端**：MQTT 发布/订阅主题见 5.2；上报频率 = 采集周期 800ms 驱动。
- **对现场设备**：Modbus RTU 主站，只读（0x03），不支持写/广播。
- **对用户**：触摸 UI（主界面/设置/WiFi/日志/关于）；UART5 115200 调试口（联网阶段事件 + `[LOG]` 日志镜像 + OneNET 回执）。

# 7. 构建、烧录与部署

## 7.1 开发环境

| 项 | 版本 / 说明 |
|---|---|
| CubeMX | 6.18.1（FW_F4 V1.28.3，`.ioc` 导入） |
| 工具链 | arm-none-eabi-gcc（**STM32Cube 自带 bundle**；Homebrew 版缺 newlib 不可用） |
| 构建系统 | CMake ≥3.22 + Ninja（preset 驱动，工具链文件在 preset 内） |
| 下载/调试 | openocd + ST-Link（网关）；pyocd + CMSIS-DAP（从机） |
| 编译数据库 | compile_commands.json（clangd 用） |

## 7.2 构建流程

```bash
make                # = cmake --preset Debug && cmake --build --preset Debug
make slave          # 从机独立构建（ModbusSlave/build/）
make size           # Flash/RAM 占用统计
```

**注意**：必须走 preset（工具链在 CMakePresets.json 里）；手工 `cmake -S . -B build` 会用宿主编译器配置、在启动文件报 unknown directive。`User/*.c` 是 GLOB_RECURSE 收集，**新增源文件需重新 configure**。构建前确认 `.env` 存在（否则云凭据为占位值，连接必失败）。产物：`build/Debug/industrial-edge-gateway.{elf,bin,map}`。

## 7.3 烧录

```bash
make flash          # 网关：openocd + ST-Link
make flash-slave    # 从机板：ST-Link/CMSIS-DAP 换接从机 SWD 后
make reset / make openocd   # 复位 / 起 gdbserver
```

常见失败：`init mode failed (unable to connect)` → 按住复位键烧录（固件状态妨碍调试口时唯一解）或降速 `adapter speed 480`；确认插的是目标板的 SWD、SWD 排针无其他信号线搭接（详见 `docs/调试排查手册.md`）。

## 7.4 现场部署

1. **开机校准**：首次上电（或 W25Q 无校准数据）自动出红十字校准，按左上、右下十字中心各一次；**按住屏幕开机可强制重新校准**。
2. 屏点亮主界面；10s 无操作息屏、触摸唤醒。
3. UART5 115200 接终端看联网阶段输出与 `[LOG]` 日志镜像。
4. 接从机板 RS485（A/A、B/B、**共地**）：屏幕数据 800ms 刷新，日志出现 `modbus back online`。
5. WiFi 座插 ESP8266，设置页配网；MQTT 连上后屏幕 ONLINE；断网测缓存（LED1 亮/WARN 日志）、恢复后自动补传（LED2 亮、`BUCHUAN*1`）。

## 9.3 遇到的问题与解决办法

| 编号 | 描述 | 状态 | 计划 | 解决办法 |
|---|---|---|---|---|
| ISSUE-001 | 长时间待机熄屏后，屏幕无法唤醒 | 已解决 | — | 与调试手册 #2 同源：唤醒只认 PEN 引脚，UI 循环每轮检测按下即重置空闲计时并点亮背光（PF10），唤醒那一次按压用 `lv_indev_wait_release` 吞掉、不误触按钮。若再复现：先按 9.2 查 PEN 电平与 PF10 |
| ISSUE-002 | 传输的数据只有温湿度等数值，未加具体时间戳 | 未解决 | 增加 RTC 实时时钟功能 | （注：现已由 clock.c + SNTP 校时提供墙钟，payload 时间戳仍未加） |
| ISSUE-003 | 断开 RS485 后屏幕 10s 熄屏（PF10=0），重连 RS485 数据唤醒成功但 PF10 仍=0 不亮屏；触摸/WiFi 状态变化唤醒也无效 | 已解决 | UI 任务函数中，数据唤醒没有增加标志位判断，计划增加标志位判断后重试 | 根本原因是 page_main.c 中的引脚出错，导致 PF10 没有被正确置位 |
| ISSUE-004 | 复位后初始网络可连（ONLINE），运行中切换网络一直连不上，切回初始网络也不行，须复位恢复 | 已解决 | | 根因三层：CWAUTOCONN=0 被模块 busy 窗口静默吞掉（RST 后自连旧网）、busy 无 ERROR 关键词只能超时且重试策略错位、开机路径掩盖问题。修复：关自连重试到 OK、CWJAP 对 TIMEOUT 4 次重试/ERROR 快失败、join 失败不再 CIPSTART（调试手册 #7 案例） |
| ISSUE-005 | （补记）MQTT 任务循环结构缺陷致同优先级 AT 任务锁车队饿死（分钟级无法调度） | 已解决 | | 让位延时 vTaskDelay(2000) 必须留在循环体内（tasks.c:172 注释）；同优先级共享锁必须主动让位 |

# 10. 运维与升级

## 10.1 日志查看

屏幕"日志页"倒序读 W25Q（最新置顶、10 行、按级别三色：INFO 灰白 `C_TEXT` / WARN 琥珀 `C_WARN` / ERROR 浅红 `C_FAIL`），或 UART5 看 `[LOG][INFO|WARN|ERROR] 消息` 镜像（纯文本，级别标签与屏幕三色同义）。时间戳为 `T+HH:MM:SS` 运行时长（非墙上时间）。常见关键字：`modbus offline/back online`、`wifi timeout/denied`、`connack failed`、`MQTT disconnect`、`BUCHUAN*1/Finish`、`scan FAIL`。

## 10.2 固件升级（OTA / 本地）

当前仅支持本地 SWD 烧录（`make flash`），**无 OTA**。`make flash` 只擦写 MCU 片内程序区，W25Q 里的日志/缓存/校准/凭据不受影响。OTA（bootloader + 双区 + 回滚）列入远期规划（W25Q 8~16MB 空闲区可放备用镜像）。

## 10.3 故障处理

现场三板斧：① 看灯（docs/指示灯.md 组合表）定位阶段；② 看屏（状态字 + 日志页）定位事件；③ 接 UART5 取证。整机异常 → 断电重上电（清 SWD/模块僵死状态）；仍异常 → 按住复位烧录最新固件。周期 20s 复位 = 看门狗在收尸，按软死锁排查。
