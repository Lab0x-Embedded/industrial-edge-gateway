# 调试排查手册（面试精选版）

本项目开发/联调过程中实际遇到的问题复盘，只保留面试有讲述价值的案例。
格式：现象 → 根因 → 修复 → 面试讲法。完整 27 例原文在 git 历史：`git show HEAD:docs/调试排查手册.md`。

---

## 一、系统与并发

### 案例 1：开机白屏，约 20 秒复位一次（循环）

- **现象**：上电白屏，每 ~20s 闪一次，无限循环。
- **根因**：队列/互斥锁只声明未创建（堆 15KB 连任务栈都放不下，`xTaskCreate` 静默失败返回 NULL），UI 任务拿 NULL 句柄触发 `configASSERT` 关中断死循环，看门狗（20s）无人喂。
- **修复**：`MX_FREERTOS_Init` 补建队列/互斥锁，堆 15K→32K，创建类调用全部检查返回值。
- **面试讲法**："复位/闪烁周期 ≈ 看门狗超时值"是软死锁的指纹——周期对上就去找关中断死循环（断言/Error_Handler），再用调试器 halt 看 PC 直接实锤。顺带的教训：FreeRTOS 创建类 API 失败是静默的，不查返回值就是埋雷。

### 案例 2：多任务并发操作同一颗 Flash（隐患修复）

- **现象**：日志/缓存/凭据/校准四个使用方在不同任务里碰 W25Q，SPI 事务可能被抢占交错。
- **根因**：一条 Flash 事务是"CS 低 → 命令 → 数据 → CS 高"的序列，WREN/擦除还是芯片全局状态；任务 B 从中间插入，两条事务的字节交错，双方全部作废——症状与驱动 bug 无法区分。
- **修复**：`flash_mutex` 做**全芯片**互斥，在 w25qxx 驱动层统一持有，log/cache/凭据/校准共用。
- **面试讲法**：锁的粒度要对齐"物理资源的完整事务"而不是"函数调用"。NOR 的命令序列是芯片级的，按扇区加锁没用。

### 案例 3：CubeMX 重新生成代码后开机死机

- **现象**：重生成代码后白屏不开机，代码 diff 看不出问题。
- **根因**：TIM4 是 HAL 时基（SysTick 归 FreeRTOS），.ioc 里时基中断记录非标，重新生成**不产出** `TIM4_IRQHandler`，首次 1ms 中断落入 startup 默认死循环。
- **修复**：恢复 handler；把"重生成后核对 stm32f4xx_it.c 的 TIM4_IRQHandler"写进 README 检查清单。
- **面试讲法**：代码生成器省的时间会在"生成结果不完整"里还回去——重生成后必须过一遍关键中断入口清单；openocd halt + `addr2line` 定位到 startup 默认 handler 是实锤手段。

## 二、通信与云

### 案例 4：WiFi 用着用着永久失联，扫描永远失败（ORE 聋哑）

- **现象**：运行一段时间后 AT 全部超时、热点扫描永远失败；模块本身正常（手机能搜到它的 AP），复位板子才恢复。
- **根因**：UART4 出过一次溢出错误(ORE)后 RX 永久停摆——HAL 出错时会**中止** `ReceiveToIdle_DMA` 且不自动重启，而项目没实现 `HAL_UART_ErrorCallback`（CubeMX 只给空弱定义）→ 回调再也不会触发。日志写 W25Q 占住中断响应的窗口里来的字节就丢 → ORE，**用得越久越必然发生**。
- **修复**：实现 `HAL_UART_ErrorCallback`：清 ORE 标志 + 立刻重挂 DMA + 关回 HT 中断；另加任务级 `rx_selfcheck()` 定期巡检 `huart4.RxState`，没挂着就重挂。
- **面试讲法**："TX 正常、RX 全丢、模块没死"→ 分清"模块死了还是 MCU 聋了"，读 `RxState` 一条自检就知道。核心教训：**HAL 的弱回调不实现 = 外设静默死亡**，这类 bug 不报错、不复现于调试期，是嵌入式最阴的一类。

### 案例 5：环形缓冲"满"边界把整个缓冲判为空

- **现象**：偶发的 AT 应答整段丢失。
- **根因**：判空/判满都靠"读指针追上写指针"，写满到 length==BUFFER_SIZE 时两指针重合 → `GetLength()==0`，新数据 + 原有未读数据一起被当成空。差一个空槽（off-by-one）。
- **修复**：`GetRemain()` 改为 `BUFFER_SIZE - 1 - length` 恒留一个空位；索引加 `volatile`（会被内联进逐字节读的紧循环）。
- **面试讲法**：环形缓冲的空/满歧义是经典考点——我踩的版本还多一层真实复现方法：把读写逻辑抄成主机侧 30 行 C 程序跑边界用例（存 1792B 再写 256B），比在板上猜快得多。

### 案例 6：OneNET 显示在线但收不到数据（5 个 bug 叠加）

- **现象**：平台显示设备在线，数据点一条没有。
- **根因**（逐层剥开）：① 重连函数盲发 30 次后无条件置在线（假在线）② connect 标志锁死离线判定 ③ 实时数据组包后缺发送调用 ④ 物模型格式应为 `{"x":{"value":..}}` 包装 ⑤ nano.specs 默认禁 `%f`，payload 浮点输出为空。
- **排查**：串口抓实际发布内容看到 `"temperature":,`（空值）锁定浮点；平台回执 `code 10411` 锁定物模型标识符不符。
- **修复**：严格 CONNACK 校验、删假在线标志、补发送调用、改包装格式、链接加 `-u _printf_float`。
- **面试讲法**：协议栈每层都有应答（CONNACK→PUBACK→平台 code 回执），**自上而下逐层验证**，哪层应答断了 bug 就在哪层之下——5 个 bug 分别在不同层现形，一次串行拔完。

### 案例 7：运行时切换 WiFi 永远连不上，复位才恢复

- **现象**：换 WiFi 后日志循环 `wifi timeout`，切回原网络也一样。
- **根因**（三层叠加）：① `AT+CWAUTOCONN=0` 单发一次且不看返回——发令时模块正忙于自己的上电自动重连（busy 窗口），指令被静默丢弃；CWJAP 成功过就把 AP 写进模块 flash，之后每次 `AT+RST` 都唤醒模块自动连旧网 ② `busy p...` 不含 ERROR/FAIL 关键词，命令层只能等满 15s 超时，而 join 只对 ERROR 重试 → CWJAP 每轮实际只发一次且被钉死在模块必忙的相位 ③ 开机路径的 join 失败被无视、CIPSTART 骑在模块自动连好的网上照样 ONLINE，把前两个问题全掩盖。
- **修复**：`CWAUTOCONN=0` 重试到 OK（≤10 次）；join 对 TIMEOUT 重试 4 次吸收 busy 窗口、对 ERROR（真密码错）只补试一次快失败；join 失败即收场不再 CIPSTART。
- **面试讲法**：对比"开机路径能连、重连路径必败"→ 差异点（RST）就是指路牌。区分"环境性失败可重试"和"确定性失败快失败"是外设连接管理的核心设计原则。

### 案例 8：设置页点「连接」必败，开机自动入网却正常

- **现象**：同上，但定位更快——两条路径唯一差异是重连路径多了 `AT+RST`。
- **根因**：模块软复位后 1~3s 才重新应答 AT，原流程盲等 1s 就发后续命令，全部落进启动窗口被丢，且每次都死在同一相位，"稳定地失败"。
- **修复**：`wifi_at_wait_ready()`：复位后反复发 `AT` 探测直到 OK（≤8s）再走业务。
- **面试讲法**：对外设模块的状态迁移，**用探测确认替代固定延时**——平均更快、最坏有界。

## 三、存储

### 案例 9：日志写了 20 条，一条都读不回（NOR 静默写失败）

- **现象**：`wptr=1520` 在涨，偏移 0 处 `m=0000`、时间戳是旧数据。
- **根因**：`WaitForWriteEnd` 超时 ~20ms < 扇区擦除 45~400ms，超时后软件以为写完了；且**超时路径不释放 CS** → 芯片卡在连续状态读模式 → 后续 WREN/PageProgram 全部被吞。
- **排查**：诊断信息分层加码（wptr→sz→id→m/ts→sr）：flash ID 正常排除芯片损坏、m=0000+旧时间戳=擦除从未生效，根因锁定驱动层。
- **修复**：忙等改 `HAL_GetTick()` 墙钟 500ms 超时 + **所有退出路径都拉高 CS**；同路径的断网缓存随之修复。
- **面试讲法**：NOR 的失败是静默的（不置位不报错），防御要洋葱式：超时按最坏擦除时长定、退出路径保证总线释放、关键数据写后回读。**外设驱动的退出路径和主路径同样重要。**

### 案例 10：日志指针 144，不是 76 的倍数（结构体填充）

- **现象**：日志错位成乱码，`wptr=144` 与条目 76B 对不上。
- **根因**：`Log_Obj` 末尾 `uint16_t magic` 产生尾部填充，`sizeof` 跨构建歧义（72/76），写读两侧步长不一致，魔数永不对齐。
- **修复**：magic 改 `uint32_t` 且放结构体最后，恰好 76 字节无填充。
- **面试讲法**：落盘结构体要么 `packed` 要么设计成天然无填充并用 static_assert 锁死——sizeof 的二义性是跨模块/跨构建数据错位的隐形来源。

## 四、显示与触摸

### 案例 11：颜色连环坑——反显与 BGR 两个独立开关

- **现象**（三阶段）：① 深色 UI 显示成白底灰卡片 ② 关掉反显后蓝色按钮变橙、温度弧变蓝紫 ③ 一度改错方向又改回来。
- **根因**：两个独立的显示开关叠在一起——`0x21` 整屏反显（继承自原工程的亮色主题配置）+ MADCTL 的 BGR 位与面板像素序不匹配。带反显状态下调 BGR，判断被污染，得出过错误结论。
- **修复**：反显关（`0x20`）+ BGR=1（MADCTL=0x68），并用固定验收色验证：连接按钮=蓝、温度弧=红、湿度弧=青绿。
- **面试讲法**：颜色错误要先分类（蓝↔橙=R/B 互换；整体洗白=反显），**两个独立变量必须分开验证再组合**，在污染状态下做的判断不可信。用已知色值逐一对号（`#60A5FA` 显示为 `#FAA560`）是硬证据。

### 案例 12：控件尺寸莫名变 130×130（LVGL 样式语义）

- **现象**：顶栏变成屏幕中间一个 130x130 方块，怎么调都不在顶部。
- **根因**：`lv_obj_remove_style_all()` 会把 WIDTH/HEIGHT 本地样式一起删掉；写成先 `set_size()` 再 `remove_style_all()`，尺寸被删后对象退回类默认值 `LV_DPI_DEF`=130x130。
- **修复**：顺序固定为 `remove_style_all` → `set_size` → 再设颜色/圆角。
- **面试讲法**：LVGL 里"删除全部样式"包含本地样式是文档不显眼的语义；更一般的教训是别拿"看起来正常"当验收——`lv_arc` 默认恰好 130x130，同样错序却不露馅。

### 案例 13：触摸三连——时序、映射、持久化

- **现象**：① 完全无反应 ② 有反应但点位不对 ③ 换板后漂移。
- **根因/修复**：① 自写 XPT2046 时序无延时、移位 `>>3`（应 `>>4`）读数错位——按厂商例程逐条对照重写（1µs/沿、命令后 6µs 建立）；② 映射常数写死不通用——改开机两点校准（左上/右下十字、16 次采样取平均、逐轴仿射），校准值持久化 W25Q；③ 校准存在主板不跟屏走——加"按住屏幕开机强制重校准"。
- **面试讲法**：位 banging 的模拟时序外设，**厂商驱动就是标准答案**，自己发明时序就是发明 bug；校准数据要考虑"跟谁走"的生命周期。

### 案例 14：换一块板触摸彻底失效（openocd 当听诊器）

- **现象**：固件在别的板子正常，这块板触摸完全无反应。
- **根因**：板上排针复用，跳线帽不在 LCD 侧，PEN 被外部持续拉低，固件认为"永远按下"。
- **排查**：openocd 非侵入采样 PF11 输入寄存器，11 秒 22 次全为低 → 外部拉低实锤（固件两板一致可先排除软件）。
- **面试讲法**：openocd/gdb 是免 IDE 的硬件听诊器——halt 看 PC、`addr2line` 映射源码行、`mdw` 实时采样引脚电平，不改一行代码就能读硬件状态。

### 案例 15：屏幕数值恒 0，云端正常时也 0

- **现象**：温湿度/光照一直显示 0。
- **根因**：UI 数据队列只在"云端在线"分支才被写入，离线即冻结。
- **修复**：采集任务每 800ms 直写 UI 队列（`xQueueOverwrite` 邮箱语义），显示与云端状态彻底解耦。
- **面试讲法**：数据链路设计要让**每个消费者独立成活**——显示不能以"上云成功"为前提，反压/冻结都会造成"云好屏坏"的假故障。

## 沉淀的通用经验（面试可引用）

1. **周期性复位先算周期**：闪烁/重启周期 ≈ 看门狗超时 → 关中断死循环（断言/Error_Handler）。
2. **openocd 是免 IDE 的听诊器**：halt+PC+`addr2line` 定位死点；`mdw` 采样外设寄存器/引脚电平；直读 RAM 判外设死活。
3. **诊断信息分层加码**：一次加一个变量（wptr→sz→id→m→sr），每轮排除一个假设。
4. **HAL 的弱回调漏实现 = 静默停摆**：ErrorCallback 不实现就只有空函数体，外设出错后中止传输且不重启。
5. **"模块死了"还是"我们聋了"用一条自检分清**：读 `huartX.RxState` 判断接收是否还挂着。
6. **协议栈逐层验证**：每层应答（CONNACK→PUBACK→平台 code）都是断点，哪层断 bug 就在哪层之下。
7. **两条路径对比**：能连/必败的差异点就是指路牌；固定延时换探测确认。
8. **外设"不说话"先查供电，再接线，最后固件**：射频模块发射瞬间电流尖峰大，供电弱则整机失联而 MCU 自检全"正常"。
9. **nano.specs 三件套**：`%f` 要 `-u _printf_float`；printf 输出空值先查这个。
10. **FreeRTOS 句柄类 API 拿 NULL 不一定崩**：创建类调用集中一处、全部查返回值。
11. **环形缓冲/边界逻辑在主机侧跑小模拟**：30 行 C 跑满/空/回绕，比在板上猜快。
12. **厂商例程是时序类外设的标准答案**；**落盘结构体要消除 sizeof 二义性**。
13. **诊断脚手架用完就删**：根因确认后清掉临时自检，留下真修复，否则自检行本身成为新噪声。
