## 沉淀的通用经验

1. **"周期性复位"先算周期**：闪烁/重启周期 ≈ 看门狗超时时间 → 八成是关中断死循环（断言/Error_Handler）。
2. **openocd 是免 IDE 的听诊器**：halt+PC+`addr2line` 定位死点；`mdw` 读外设寄存器实时采样引脚电平（PEN 诊断）；直读 RAM 变量判传感器死活——都不需要改一行代码。
3. **诊断信息分层加码**：一次加一个变量（wptr→sz→id→m→sr），每轮排除一个假设，比一次全上更快定位。
4. **厂商例程是时序类外设的标准答案**：SPI/单总线这类位 banging 驱动，自写时序对不上时直接逐字节对照厂商代码（>>4 vs >>3 差一个位就是天壤之别）。
5. **换板必失灵的东西清单**：跳线帽位置、校准类数据（存在板载 Flash）、排线插到位、SWD 电压读数——先查这四样再怀疑软件。
6. **nano.specs 三件套**：`%f` 要 `-u _printf_float`；malloc 行为不同；stdio 更精简——嵌入式 printf 输出空值先查这个。
7. **FreeRTOS 句柄类 API 拿到 NULL 不一定崩**：`xTaskCreate` 失败静默返回，任务凭空消失；创建类代码集中在一个可核对的地方。
8. **HAL 的弱回调漏实现 = 静默停摆**：`HAL_UART_ErrorCallback` / `HAL_xxx_ErrorCallback` 不实现就只有空函数体，外设出错后 HAL 中止传输且不重启——"设备用着用着就不通了"先查这几个回调在不在（本项目就是漏了 UART 的那个）。
9. **"模块死了"还是"我们聋了"，要用一条自检分清**：读 `huartX.RxState` 判断接收是否还挂着，比换模块、换线快得多（本项目的 `RX:DEAD` 自检行）。
10. **环形缓冲的边界要用主机侧小模拟验**：把读写指针逻辑抄到一个 30 行 C 文件里跑边界（满/空/回绕），比在上位机上猜快得多——本项目就是这么复现出"满边界把整缓冲判为空"的。
11. **收到别人的缺陷分析先逐条对代码**：同一份分析里往往混着"真 bug / 合理加固 / 误判"三类，全盘接受会引入无谓改动，全盘否定会漏掉真问题。
12. **外设"不说话"先查供电，再查接线，最后才怀疑固件**：ESP8266 这类射频模块发射瞬间电流尖峰大，供电稍弱就整机失联（AT 不回、数据不收），而 MCU 侧一切自检都"正常"——本项目最终就栽在这里。
13. **诊断脚手架用完就删**：临时自检行/计数/抓包上屏在根因确认后应清掉（本项目 Flash 因此少 1.4KB），但要留下"无声自愈"这类真修复；否则"一堆永远显示 0 的自检行"本身就成了新负担。
