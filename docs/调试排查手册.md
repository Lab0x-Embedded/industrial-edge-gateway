# 调试排查手册

本项目移植/联调过程中实际遇到的问题复盘。格式：现象 → 可能原因 → 排查方法 → 解决方案。

| # | 现象 | 可能原因 | 排查方法 | 解决方案 |
|---|------|----------|----------|----------|
| 1 | 开机白屏，约 20 秒闪一次 | 队列/互斥锁只声明未创建，UI 任务拿到 NULL 句柄触发 `configASSERT` 关中断死循环，看门狗（20s）无人喂 → 周期性复位 | 闪烁周期≈IWDG 超时时间即高度怀疑断言挂死；调试器 halt 看 PC 停在断言死循环 | `MX_FREERTOS_Init` 补建队列/互斥锁；堆 15K→32K（原大小连任务栈都放不下，`xTaskCreate` 失败不报错） |
| 2 | 息屏后触摸点不亮 | 空闲计时只在 MQTT 状态变化时重置，触摸从不重置 | 审 UI 任务循环：`idle_tick` 的所有写入点 | UI 循环检测 PEN 引脚：按下重置计时并点亮；`lv_indev_wait_release` 吞掉唤醒那次按压防误触 |
| 3 | 触摸完全无反应 | ① XPT2046 时序错：时钟无延时贴 2MHz 上限、命令后无建立时间、16 位读数 `>>3`（应 `>>4`）读数错位翻倍 ② 压力过滤公式误杀有效触摸 | 屏上临时调试标签显示 PEN 电平与 X/Y 原始值，分三级定位（无 PEN/有 PEN 数值死/数值变但错位）；与厂商例程逐条对照时序 | 按厂商驱动重写时序（1µs/沿、命令后 6µs、`>>4`）；删压力过滤；双读 ±50 抗抖 |
| 4 | 触摸有反应但点位不对 | 移位错误导致读数整体错位；写死的映射常数与实际屏不符 | 按固定位置记录原始值（如按左上角读到 2819/525），与预期量程比对 | 开机两点校准（左上/右下十字），映射自动推导、支持镜像；校准值持久化 W25Q 参数区 |
| 5 | 蓝色按钮显示橙色、青绿显示粉色 | ① 面板像素序与 MADCTL(0x36) 的 BGR 位不匹配 → 红蓝通道互换（蓝↔橙是典型特征）② 同时叠了整屏反显（青绿↔粉色是反显特征，见 #20） | 拿已知颜色控件对照（蓝↔橙互换=像素序；蓝↔青、绿↔粉=反显） | **最终结论：MADCTL=0x68（BGR 位=1）+ 反显关（0x20）**。当时改成 0x60 是在还带反显的状态下判断的，判断被污染；关掉反显后 R/B 互换才暴露出来 |
| 6 | 换一块板后触摸彻底失效 | 板上排针复用（P12 与 LCD 共用），跳线帽不在 LCD 侧，PEN 被外部拉低，固件认为"永远按下"卡死 | openocd 实时采样 PF11 输入寄存器 11 秒 22 次全为低 → 外部拉低实锤 | 跳线帽拨到 LCD 侧；诊断时先怀疑接线/配置，固件两块板一致可排除软件 |
| 7 | 换板后触摸点位漂 | 触摸校准存在**主板**的 W25Q 里，不跟屏幕走；换板后读到别的板的旧校准值 | 开机是否进校准界面（无有效数据会自动进） | 增加"按住屏幕开机强制重新校准"入口，换板/换屏/漂移通用 |
| 8 | CubeMX 重新生成代码后开机白屏死机 | TIM4 被 CubeMX 占用为 HAL 时基（FreeRTOS 占 SysTick），.ioc 里时基中断记录非标 → 重新生成**不产出** `TIM4_IRQHandler` → 首次中断进默认死循环 | openocd halt 看 PC；`addr2line` 解码落在 startup 默认 handler | 恢复 handler；确认 CubeMX 正常生成后即稳固；灰色=被时基占用属正常 |
| 9 | 屏幕温湿度光照恒为 0（云端正常时也 0） | UI 数据队列只在"云端在线"才被写入，离线即冻结在 0 | 链路分析：找 `lvgl_data_queue` 的全部写入点 | 采集任务每 800ms 直写 UI 队列，与云端状态解耦 |
| 10 | Modbus 全程读不到（offline 日志） | 从机固件没烧/没跑、RS485 A/B 未接或接反 | ① 日志页看 `modbus 0x0X offline`（连续 5 次问询失败≈开机 4 秒）② 调试器直读从机 RAM 传感器变量确认从机死活 ③ PC 端 `tools/modbus_master_test.py` 绕开网关点名从机 | 烧从机固件、A 对 A/B 对 B 接线、两板共地 |
| 11 | 从机温湿度停在默认值 25.6/58.4 不变化 | 固件 DHT 引脚（PB9）与实际接线（PA15）不符，`DHT_Read` 全部失败沿用默认值 | 调试器读从机 RAM：`temp_raw` 恒为默认值 256 → 传感器读取失败而非通信失败 | 引脚改成实际接线 PA15；换算值在 RAM 里跳变即恢复 |
| 12 | 调试器报 "unable to connect"，且 Target voltage 显示 4.89V | 传感器 5V 供电线误插到 SWD 排针（Vref 应为 3.3V）或 DATA 碰到 PA13/PA14 调试口 | 看 ST-Link 电压读数：≠3.2~3.3V 就是接线错误 | DHT 用 3.3V 供电（支持 3.3~5.5V），5V/GND 远离 SWD 排针 |
| 13 | 板子莫名"停住"，halt 显示 breakpoint | 之前调试会话留下的硬件断点未清（VS Code 断点面板残留） | openocd halt 显示 "halted due to breakpoint" 且 PC 在正常代码处 | `rbp all` 清全部断点；调试结束养成清断点习惯 |
| 14 | OneNET 显示在线但收不到数据（多重叠加） | ① 重连函数盲发 30 次后无条件置在线（假在线）② `connect` 标志锁死离线判定 ③ 实时数据组包后缺发送调用 ④ 物模型格式应为 `{"x":{"value":..}}` 包装 ⑤ nano.specs 默认禁 `%f`，payload 浮点输出为空 | 串口抓实际发布内容：`"temperature":,`（空值）→ 锁定浮点；对照平台回执 `code`（10411=物模型标识符不符） | 严格 CONNACK 校验、删 connect 标志、补发送调用、改包装格式、链接加 `-u _printf_float` |

## 沉淀的通用经验

1. **"周期性复位"先算周期**：闪烁/重启周期 ≈ 看门狗超时时间 → 八成是关中断死循环（断言/Error_Handler）。
2. **openocd 是免 IDE 的听诊器**：halt+PC+`addr2line` 定位死点；`mdw` 读外设寄存器实时采样引脚电平（PEN 诊断）；直读 RAM 变量判传感器死活——都不需要改一行代码。
3. **诊断信息分层加码**：一次加一个变量（wptr→sz→id→m→sr），每轮排除一个假设，比一次全上更快定位。
4. **厂商例程是时序类外设的标准答案**：SPI/单总线这类位 banging 驱动，自写时序对不上时直接逐字节对照厂商代码（>>4 vs >>3 差一个位就是天壤之别）。
5. **换板必失灵的东西清单**：跳线帽位置、校准类数据（存在板载 Flash）、排线插到位、SWD 电压读数——先查这四样再怀疑软件。
6. **nano.specs 三件套**：`%f` 要 `-u _printf_float`；malloc 行为不同；stdio 更精简——嵌入式 printf 输出空值先查这个。
7. **FreeRTOS 句柄类 API 拿到 NULL 不一定崩**：`xTaskCreate` 失败静默返回，任务凭空消失；创建类代码集中在一个可核对的地方。
